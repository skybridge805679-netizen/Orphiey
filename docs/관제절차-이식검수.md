# 관제 절차 이식 검수

## 확인된 원인과 이번 수정

대조 대상은 저장소에 내장된 CTC LAB(v0.39.60, 원본 b10c1d2)이다. 동시 개발 중인 외부 CTC LAB 최신 버전을 검사했다는 뜻은 아니다. `ctc/`는 수정하지 않았다.

| 문제 | 근거 | 수정 위치 |
|---|---|---|
| 관계역 통보 누락 | `ctc/engine/emergency-data.js` 비상05 통보14에 금천구청·독산·가산디지털·구로역, 변경 선로·무정차 통과·안내방송이 명시됨. 기존 3장은 이 호출 없이 n14 확인 처리 | 3장에 네 역의 개별 호출·수신 확인 복원 |
| 진로보다 먼저 출발 지시 | 원본은 통보14에 진로 개통, 통보15에 기관사 출발 지시. 기존 게임은 반대 | 3장과 최종장 진로 개통 뒤 기관사 지시로 순서 변경 |
| 진로만 열어도 조기 출발 | `fts-builtins.js`는 통보 또는 목적지 진로 중 하나만 충족해도 출발 반응을 생성함. 비상05 `r-n15`의 실제 조건에서도 확인 | 게임의 비상05 문제 로딩 시 통보 조건을 유지하고 진로만으로 출발하는 대체 조건 제거 |
| 출발을 다른 조건보다 먼저 말할 수 있음 | 호출의 모든 필수 문장이 같은 단계에서 섞여 나옴 | `last:true` 문장은 나머지 필수 지시 뒤에만 표시. 3장 3개 출발 호출 및 최종장에 적용 |
| 열번 수정·삭제 자동 대행 | 기존 3장의 `do.rename`, `do.del` | 기존 원본 목표를 쓰는 수동 조작으로 교체(이후 LS 열번창 우클릭 기본으로 변경, 3·4·6·7·8장 전부). 출발 전 수정, 연결 후 중복 알람 확인, 합병 승인 후 삭제 |
| 중복 알람 은폐·자동 확인 | `ctc-drill.js`의 `alarms()`가 중복 알람을 걸러내고 `update()`가 자동으로 `clearAlarms()` 호출 | 두 처리 제거. MMI 표시·개별 체크·확인 복원. 체크하지 않고 확인만 누르면 유지 |
| 조작 누락이 통과로 보임 | `dkOps`가 없는 목표를 제거하고 `missed`도 성공으로 표시 | 없는 목표는 오류로 알리고 실제 달성한 목표만 성공 표시 |

구원 출발(n16)은 원래부터 통보와 열번 수정이 모두 필요했다. 고장열차 회송(n18)도 통보가 출발 조건이다. 이 부분은 게임에서 열번·진로 처리를 출발 지시 뒤에 배치한 것이 문제여서, 이번에는 출발 전에 준비하도록 이동했다. 회송 진로 재개통은 기존 시범 대행을 유지했다.

## 실행 검증

- `node tools/drill-procedure-test.js`: 네 관계역 통보, 진로/출발 순서, 열번/알람 순서, 최종장 진로/출발 순서 검사.
- `node tools/drill-test.js ch03-rescue`: 출발 통보 n15 전 K1212 정차 유지, 통보 후 이동 검사. MMI UI로 열번 수정·삭제·알람 확인. S / 31개 판단 / 원본 목표 100점 / 상태 완료 / 놓친 목표 없음.
- `node tools/drill-test.js challenge ch03-rescue:bogie`: 이번 실행의 추가 상황은 응급환자·무전 불통. 구원 취소 후 K1208 자력운행, 후속열차 재개, 게임 결과 S 확인. 원본 FTS 상태는 종료이며 원본 전체 구원 시나리오 목표 달성을 뜻하지 않는다.
- `node tools/drill-ui-test.js`: 출발 문장 선행 선택 방지, 체크 없이 알람 확인 시 유지, 체크한 알람만 확인, 구원 취소 분기에 합병 목표가 없는지 브라우저 검사 통과.
- 문법 검사 및 `git diff --check` 통과.
- 네트워크 오류 1건은 Google Fonts CSS 차단이다. 기존 기본 글꼴로 동작한다.

## 후반 장과 상황변경의 잔여 검수 범위

다음은 소스에서 찾은 별도 검수 대상이며, 전체 정상 판정이나 철도 절차의 완전성 보장이 아니다.

| 범위 | 확인한 구조 / 남은 작업 |
|---|---|
| 1·2장 | 차량고장 초기 통제·보고를 나누고 선행 통보를 자동 확인하는 구조. 이번에는 전체 재플레이하지 않음 |
| 4장 | 운행선 변경은 교수 시범, 회송 열번 자동 변경. 관계역·기관사 지시와 실제 진로를 원본과 전부 재대조할 필요 |
| 5장 | K1137 단선지령식은 진로 조작 후 기관사 호출 구조를 확인. 상선/하선 변경 등 다른 분기와 점유·열차 도착 조건의 실제 충족은 별도 검증 필요 |
| 6장 | 구원·운행선 변경 일부가 시범. 자력운행 가능 분기의 지시·목표와 원본 대조 필요 |
| 7장 | 운행선 변경·구원 준비·열번 정리 자동 대행이 남아 있음. 탈선 분기는 본편 흐름을 대체하는 구현으로, 모든 대체 조합의 실제 열차 상태와 지시 순서 검증 필요 |
| 8장 | 회송·구원 열번 자동 정리가 남아 있음. 단선지령식/탈선 복구와 후속 운행의 조건 검증 필요 |
| 최종장 | 이번에 개통/출발 역전은 수정하고 순서 회귀 검사. 모터카 철수·관계역 통보를 포함한 전체 플레이는 이번에 미실행 |
| 3장 n18 | 원본은 K1212의 구로 진입 전/후로 주의 통보가 다르나 현재는 선행열차 주의 문구가 고정. 실시간 위치에 따른 분기 교정이 남음 |
| 다른 내장 문제 | 엔진의 통보 OR 진로 출발 준비 생성은 비상05 밖에도 적용됨. 이번 보정은 비상05 게임에 한정. 원본 CTC에서 다른 사례의 의미를 확인한 뒤 개별 적용할 것 |

원본 대본 → 게임의 호출·조작 → 엔진의 출발 조건 → 실제 열차 위치를 각각 대조해야 한다. 힌트를 따라 S 랭크를 받는 것만으로 이식 정확성을 판정하지 않는다.
